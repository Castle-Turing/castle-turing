# docs/research — the full research reports

Point-in-time literature reviews commissioned during design work, one
markdown file per report. Each is a faithful transcription of a report
that originally existed only as a rendered page outside the repo;
landing them here keeps the record readable by anything that can read
files, the same reasoning that keeps the backlog and the briefs in the
tree.

How these relate to `docs/backlog/`: the backlog entries are the
**compressed, decision-relevant** versions, written after each review
and kept current as decisions consume them — they stay authoritative
for what the project decided to do. These files are the **full
reports** behind those entries: the complete argument, the effect
sizes, the sources, and each review's own account of its limits. They
are historical records and are not updated as the project moves; check
the backlog entry (or the brief that superseded it) for current
status.

Trust discipline: every report carries its own "how much to trust
this" or "known gaps" section, and claims are marked with per-claim
verification levels ([V] verified, [V-META] record verified but
figures from memory, [R] recalled and unverified — or `[verify]` in
backlog entries). Read those sections before quoting anything onward;
several load-bearing numbers are explicitly flagged as unverified
recall.
